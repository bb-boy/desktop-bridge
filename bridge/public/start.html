DBDesktop Bridge 客户端 v0.2.9 设备管理

新手指引.

连接 ChatGPT → 安装电脑端 → 绑定电脑 → 开始使用。基础文件和终端工具来自 Desktop Commander；需要截图、点击和窗口操作时，可选择安装 Cua Driver。

  1. 1

    连接 ChatGPT

    打开 ChatGPT 网页端「插件」，选择「添加 → 添加自定义 MCP 服务器」，手动创建连接：

    名称：Desktop Bridge
    服务器地址：https://mcp.ilovestudy.de/mcp
    认证方式：OAuth

    打开 ChatGPT 插件页 ↗

    按提示使用自己的账号登录 Desktop Bridge 并授权。以后绑定电脑时，请使用同一个 Desktop Bridge 账号，否则看不到自己的设备。

  2. 2

    安装电脑端（任选一种方式）

    安装后即可使用 Desktop Commander 的文件、终端等工具。Cua Driver 是可选的桌面控制组件，需要明确启用；不会因为连接了 MCP 就自动获得屏幕控制权限。

    方式一：图形安装器

    适合不熟悉命令行的用户。无需预装 Node.js，安装器会准备 Desktop Bridge 和 Desktop Commander。按提示选择手动运行或登录后后台运行。

    Windows 安装器Mac 安装器Linux 安装器

    注意：当前图形安装器不会自动启用 Cua Driver。若需要控制鼠标、窗口和桌面，推荐下面的 npm 方式；已有图形安装的设备也可在安装 npm CLI 后启用 CUA，无需重新配对。

    方式二：npm 命令行（支持一并安装 CUA）

    适合已安装 Node.js 24 和 npm 的用户。使用客户端 v0.2.9，首次安装并启用 Cua Driver 0.38.0：

    npm install -g @justlovepl/desktop-bridge
desktop-bridge setup --with-cua
desktop-bridge status

    npm install 只安装命令行入口，setup --with-cua 才会安装、配置和检查 Desktop Bridge、Desktop Commander 以及 Cua Driver，并打开网页登录配对。CUA 为显式选择，不是默认安装。

    如果只想使用文件、终端等基础功能，把第二条改为 desktop-bridge setup。默认是后台模式；希望手动运行，可使用 desktop-bridge setup --mode manual --with-cua。

    已安装客户端，现在想开启 CUA？

    先在电脑的本地终端安装或更新 npm CLI，再运行升级命令。已绑定的设备可保留配对凭据与运行模式，无需重新绑定：

    npm install -g @justlovepl/desktop-bridge
desktop-bridge update --with-cua
desktop-bridge status

    不要通过 Desktop Bridge 自己提供的远程终端更新自身，以免中断当前连接。若设备已被解绑，必须先重新配对。

    Mac 安装成功却提示 command not found？

    如果 npm 全局安装成功，但 zsh 仍找不到 desktop-bridge，可先在终端执行：

    export PATH="$(npm prefix -g)/bin:$PATH"
rehash
desktop-bridge --version

    确认可以正常显示版本号后，执行以下命令使新终端也生效：

    echo 'export PATH="$(npm prefix -g)/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc

    仍找不到时，检查安装目录和命令链接：

    npm prefix -g
npm root -g
ls -l "$(npm prefix -g)/bin/desktop-bridge"

    如果链接不存在，需要进一步检查 npm 安装情况，而不只是修改 PATH。

    更多命令：启动、停止、切换模式与升级 
    desktop-bridge start
desktop-bridge stop
desktop-bridge restart
desktop-bridge mode manual
desktop-bridge mode background
desktop-bridge update
desktop-bridge pair

    update 更新 CLI 与已安装的 Agent，并保留配对和模式；已经启用的 CUA 会随升级保留。pair 需要本人重新在网页确认设备绑定。

    两种方式不需要重复安装。安装成功后保持电脑联网；后台模式需要当前用户登录系统。安装了 CUA 后，仍可能需要系统单独授权屏幕录制、辅助功能等权限。

  3. 3

    绑定电脑并检查权限

    安装器会打开 Desktop Bridge 的配对网页。请使用第 1 步同一个 Desktop Bridge 账号登录，核对设备名称，并在 10 分钟内确认配对。等安装窗口提示完成后，再关闭它。

    如果启用了 Cua Driver，macOS 可能需要到「系统设置 → 隐私与安全性」允许屏幕录制和辅助功能；Windows 的系统提权确认仍须在电脑上操作。安装 CUA 不会跳过操作系统或 ChatGPT 的权限确认。

  4. 4

    开始在 ChatGPT 中使用

    回到 ChatGPT 网页端，开始新对话，输入 @ 并选择 Desktop Bridge 连接。先检查设备：

    列出我的电脑，并检查哪些设备在线、工具可用

    接着测试文件操作：

    在我的桌面创建一个测试文件

    如果已启用 CUA 并完成系统授权，还可以试试：

    显示我当前电脑的桌面截图

    保持电脑联网、客户端运行；如果提示设备离线或工具不可用，请到设备管理页面查看状态。桌面操作可能仍会触发 ChatGPT 或系统确认。

安装说明与常见问题

Desktop Commander 与 Cua Driver 有什么区别？

Desktop Commander 提供读取与编辑文件、执行终端命令等能力。Cua Driver 增加截图、窗口、鼠标键盘等图形界面操作，需要通过 --with-cua 显式安装并启用。两者的权限和系统限制不完全相同。

装了图形安装器后，能补装 CUA 吗？

可以。安装 Node.js 24 与 npm CLI 后，在电脑本地终端执行 desktop-bridge update --with-cua，已配对的标准客户端会保留绑定和启动模式。不要重复创建另一份设备配置。

为什么授权后还要安装电脑端？

MCP 连接负责让 ChatGPT 访问 Desktop Bridge 服务，电脑端客户端负责在你的电脑上执行获授权的操作。两者都完成才可以使用远程设备工具。

是否必须使用同一个账号？

是。在 ChatGPT 添加 MCP 连接时的 Desktop Bridge OAuth 授权，以及电脑端配对网页登录，必须属于同一个 Desktop Bridge 账号。不同账号的设备相互隔离。

系统阻止安装或 CUA 无法操作桌面怎么办？

当前图形安装器是测试分发版：Windows 安装器未签名，Mac 安装包未签名、公证，系统可能阻止打开。不要为安装关闭系统安全防护。CUA 还需要系统允许的图形会话及必要的辅助功能/录屏权限；Mac 的授权弹窗必须在电脑上操作。

npm 命令找不到怎么办？

先确认使用 Node.js 24 且已安装 npm，重新打开终端，执行 node -v、npm -v 和 desktop-bridge --version；Mac 的 PATH 解决步骤见上方折叠说明。

Linux 可以直接双击安装脚本吗？

不一定。桌面支持时选择「在终端中运行」；否则需要通过 shell 执行下载的自解包脚本。CUA 图形操作也需要可用的桌面会话。

ChatGPT 看不到我的电脑

先确认配对已经完成、设备管理页中设备在线且工具可用、当前连接属于同一个账号。若只是离线，启动已安装的客户端即可，不必反复安装。如果新工具尚未出现在 ChatGPT，刷新连接工具列表或重新开启对话。

配对码过期或设备解绑了怎么办？

配对码有效期为 10 分钟，过期后在客户端重新发起配对（npm 用户可执行 desktop-bridge pair）。设备解绑后，原凭据立即失效，必须重新配对；普通网络断开时不要盲目删除凭据。

找不到「添加自定义 MCP 服务器」怎么办？

请确认 ChatGPT 账号或工作空间允许创建自定义 MCP 连接。若由组织管理，请联系管理员检查相关权限。
