# Desktop Bridge client 0.2.9

Large screenshot results no longer occupy a single outgoing WebSocket frame.
The Agent sends JSON through one ordered queue in fragments of at most 16 KiB,
yielding between fragments so ping/pong control frames can be processed during
an upload. The same transport is used on Windows, macOS and Linux.

Application messages remain complete JSON text messages; concurrent health and
tool responses cannot be interleaved into the same message. Failed partial sends
terminate the connection and use the existing saved-result recovery after
reconnection, without executing the command again. New transport diagnostics
record byte counts, write completion and close reasons rather than image data.
Socket write completion is not an acknowledgement from the relay.

This release also brings the previously deployed Windows screenshot viewer v8
fixes into the repository. Display-only desktop screenshots use a short-lived,
owner-scoped image endpoint instead of embedding large Base64 data in MCP text
or widget metadata. Explicit model image delivery remains available, and saved
results can be recovered without recapturing the desktop. Existing widget URLs
remain compatible.

## Installation and deployment

```sh
npm install -g @justlovepl/desktop-bridge@0.2.9
desktop-bridge update
```

Run the update in the computer's local terminal. Existing pairing, result
journals and the selected manual/background mode are preserved. Cua Driver
remains optional and keeps its separately pinned 0.38.0 release.

The npm package contains the local client and its new fragment sender. The
image endpoint, MCP response formatting and screenshot widget live in
`bridge/server` and `bridge/public` and require the corresponding relay
deployment; installing the npm client does not deploy a relay. The existing
production relay already carries these v8 screenshot changes.

## Validation

- macOS: 156 protocol/API/process assertions passed; 4 platform-specific cases
  skipped. Browser tests were excluded in accordance with `AGENTS.md`.
- Screenshot and fragment regressions: 9 assertions passed, including bounded
  frames, UTF-8 preservation, concurrent messages, ping/pong during a paced
  transfer, interrupted sends and protected image retrieval/revocation.
- Windows p111: the 4 transport regressions and 13 npm CLI tests passed on
  Node.js 24.7.0 in an isolated temporary directory, without replacing the
  installed client or changing its pairing.
- npm CLI: all 13 assertions passed on macOS. The packed CLI, offline package
  upgrade and sandbox client reinstall passed, preserving credentials, journals
  and manual/background mode. The packed Agent and transport helper were
  checked byte-for-byte against source.
- Native installer tests: 9 passed, 2 platform-specific cases skipped.
- The earlier local Mac transport patch returned 5 consecutive real desktop
  screenshots, including two 2816×1762 captures, without a disconnect during
  that verification window. This does not establish the cause of every
  intermittent proxy or network stall.
