# Feature 04 — GUI 权限、截图与安全边界

## 目标
在可控授权下使用 Cua 读取窗口、截图、点击和输入，不因为接入新工具破坏 Desktop Bridge 的权限与审计约束。

## 设计
1. GUI 工具默认禁用；启用时用户必须明确同意该设备的 GUI 控制能力；后续可分只读观察与可修改操作。
2. Driver 自身使用官方权限模式（`standard` 或 reviewed `bounded` manifest）；不使用 `--dangerously-bypass-approvals`。
3. 对截图最小化采集范围；优先窗口截图，只有必要且获得授权才获取整屏。
4. 保留结构化元素令牌、窗口身份、快照更新语义；不重试已超时或结果未知的点击/输入。
5. Desktop Bridge 现有工具结果有 8 MiB 截断及 WebSocket 10 MiB 消息上限；实现 PNG 压缩/分辨率限制或可审计的缩放策略，禁止静默丢弃后报告成功。
6. 日志不可持久化截图、键入文本、剪贴板明文与设备认证令牌；审计记录仅存动作类型、结果和任务 ID。
7. Windows 虚拟会话、锁屏、UAC 及无交互桌面时按 Cua 返回的拒绝码处理，不绕开 OS 防护。

## 验收
- [ ] 未经授权不会公开或执行 GUI 写操作。
- [ ] 截图过大有明确错误或受控缩放处理。
- [ ] 老旧元素 Token/截图 ID 被拒绝，使用新观察恢复。
- [ ] 不在日志/测试夹具留下隐私数据或密钥。
